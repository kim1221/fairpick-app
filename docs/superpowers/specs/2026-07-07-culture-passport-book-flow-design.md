# 컬처카드 — 문화 여권 단일 책 플로우 설계

- 작성일: 2026-07-07
- 상태: 대안 3 승인됨. 사용자 문서 검토 대기
- 범위: `/passport` 화면의 정보구조와 UX 재설계

## 1. 문제

현재 `/passport`는 `발견한 카드 / 다녀왔어요 / 가고 싶어요`를 세그먼트 탭으로 갈아끼운다.
`다녀왔어요`는 여권 표지부터 시작하는 책처럼 보이지만, 나머지 두 영역은 여권 색을 입힌 독립 리스트처럼
보인다. 결과적으로 사용자는 하나의 여권을 펼친 느낌이 아니라, 서로 다른 세 화면을 오가는 느낌을 받는다.

## 2. 결정

탭을 제거하고 `/passport` 전체를 **하나의 문화 여권 책**으로 만든다. 빠른 이동은 탭이 아니라 책 오른쪽에
붙은 작은 **책갈피 인덱스**로 제공한다.

페이지 순서는 다음으로 고정한다.

1. 표지
2. 신분면
3. 발견한 카드
4. 가고 싶어요
5. 다녀왔어요 도장

이 순서는 사용자의 실제 흐름과 맞춘다.

- 발견했다
- 가고 싶어 저장했다
- 다녀와서 도장을 남겼다

## 3. 화면 구조

### 3.1 표지

기존 `PassportCoverPage`를 여권 탭의 첫 페이지로 사용한다. 사용자가 `/passport`에 들어오면 항상 여권 표지부터
보거나, 마지막으로 보던 페이지가 있더라도 표지로 돌아갈 수 있는 책갈피를 제공한다.

### 3.2 신분면

기존 `PassportIdentityPage`를 확장한다.

표시 정보:

- 여권번호
- 발견한 카드 수
- 가고 싶은 문화 수
- 다녀왔어요 도장 수
- 최근 취향 카테고리

신분면은 세 탭의 요약 대시보드가 아니라, 여권 소유자 페이지처럼 보여야 한다.

### 3.3 발견한 카드 페이지

광고를 보고 열린 이벤트 카드는 “발급받은 문화 입장권”으로 취급한다. 이 페이지는 발견 기록의 원장이다.

정책:

- 데이터 출처는 `passport.discoveredCards`
- 최신 발견순으로 보여준다.
- 방문 도장이 있는 카드는 도장 표시를 얹는다.
- 저장 여부가 있는 카드는 저장됨 상태를 보여준다.
- 카드를 누르면 상세로 이동한다.
- 카드 안에서 `저장`, `길찾기`, `도장 남기기` 액션을 제공한다.

페이지가 많아지는 것을 고려해 발견 카드는 한 여권 페이지에 3~4장씩 묶는다. 67장처럼 데이터가 많으면 여러
페이지로 나뉘며, 책갈피 `발견`은 첫 발견 페이지로 이동한다.

### 3.4 가고 싶어요 페이지

저장한 이벤트는 “여행 예정 페이지”로 취급한다.

정책:

- 데이터 출처는 기존 저장/좋아요 목록
- 기본 표시 대상은 `저장됨 && 아직 도장 없음`
- 도장을 남긴 이벤트는 `다녀왔어요` 도장 페이지로 이동한 것으로 본다.
- 저장된 이벤트를 누르면 상세로 이동한다.
- 카드 안에서 `길찾기`, `도장 남기기`, 저장 취소 액션을 제공한다.

가고 싶어요도 한 여권 페이지에 3~4장씩 묶는다. 책갈피 `예정`은 첫 예정 페이지로 이동한다.

### 3.5 다녀왔어요 도장 페이지

기존 도장 페이지를 유지하되, 탭 영역이 아니라 여권 책의 후반 페이지로 편입한다.

정책:

- 데이터 출처는 `passport.stamps`
- 페이지당 도장 수는 현재 정책인 6개 유지
- 도장을 누르면 `StampDetailSheet`를 연다.
- 도장 취소는 기존 `unmarkVisited` 흐름 유지
- 위치 인증과 티켓 보상은 없다.

책갈피 `도장`은 첫 도장 페이지로 이동한다.

## 4. 빠른 이동

세그먼트 탭은 삭제한다. 대신 여권 책 오른쪽 또는 하단에 작은 책갈피 인덱스를 둔다.

책갈피:

- `표지`
- `발견`
- `예정`
- `도장`

책갈피는 화면을 갈아끼우는 탭이 아니라, 같은 책 안의 첫 페이지로 이동하는 스크롤 보조 장치다. 선택 상태도
세그먼트 컨트롤처럼 강하게 보이지 않고, 현재 페이지가 속한 장만 은은하게 표시한다.

## 5. 데이터 모델

`passport.tsx` 안의 `segment` 상태를 제거하고, 렌더링 전용 페이지 모델을 만든다.

예상 타입:

```ts
type PassportBookPage =
  | { type: 'cover' }
  | { type: 'identity' }
  | { type: 'discovered'; pageIndex: number; items: SavedTicketItem[] }
  | { type: 'wishlist'; pageIndex: number; items: SavedTicketItem[] }
  | { type: 'stamps'; pageIndex: number; stamps: PassportStamp[] }
  | { type: 'empty'; section: 'discovered' | 'wishlist' | 'stamps' }
  | { type: 'error'; section: 'discovered' | 'wishlist' | 'stamps' };
```

함수 책임:

- `buildPassportBookPages`가 표지부터 도장까지의 전체 페이지 배열을 만든다.
- `getPassportSectionIndexes`가 `표지/발견/예정/도장` 책갈피의 시작 인덱스를 계산한다.
- 페이지 chunk 크기는 발견/예정 3~4장, 도장 6개로 둔다.

이 로직은 화면과 분리해 단위 테스트한다.

## 6. 렌더링 구조

현재 `ScrollView horizontal pagingEnabled`는 페이지 수가 많아질 때 비효율적이다. 책 전체는 가로 `FlatList`로
바꾸고 `pagingEnabled`, `getItemLayout`, `scrollToIndex`를 사용한다.

구조:

- `PassportBookPager`
  - 전체 페이지 가로 페이징
  - 현재 페이지 인덱스 추적
  - 책갈피 클릭 시 `scrollToIndex`
- `PassportIndexRail`
  - `표지/발견/예정/도장` 이동
  - 현재 장 표시
- `PassportTicketPage`
  - 발견/예정 페이지 공통 종이면
  - 티켓형 카드 3~4장 표시
- 기존 `PassportCoverPage`, `PassportIdentityPage`, `PassportStampPage`, `StampDetailSheet` 재사용

## 7. 상태와 오류

로딩, 빈 상태, 오류도 여권 밖 배너가 아니라 책 안의 페이지로 표현한다.

- 발견 로딩: 발견 장의 종이 페이지 안에서 로딩
- 저장 로딩: 예정 장의 종이 페이지 안에서 로딩
- 여권 오류: 신분면 이후 발견/도장 장에 오류 페이지 표시
- 저장 오류: 예정 장에 오류 페이지 표시
- 빈 상태: 각 장의 빈 종이 페이지 표시

상단에 큰 오류 박스가 따로 뜨지 않도록 한다.

## 8. 사용자 흐름

### 홈에서 카드 오픈

1. 홈에서 광고를 본다.
2. 이벤트 카드가 열린다.
3. 티켓이 적립된다.
4. 해당 이벤트는 여권의 `발견한 카드` 장에 자동으로 들어간다.

### 발견한 카드를 저장

1. 여권의 발견 장에서 카드를 본다.
2. 마음에 들면 저장한다.
3. 같은 여권 안의 `가고 싶어요` 장에도 나타난다.

### 다녀온 뒤 도장 남기기

1. 발견 장 또는 예정 장에서 `도장 남기기`를 누른다.
2. 이벤트가 `다녀왔어요` 도장 장에 찍힌다.
3. 예정 장에서는 기본적으로 빠지고, 발견 장에는 도장 표시가 남는다.

## 9. 테스트

필수 테스트:

- `buildPassportBookPages`가 `cover → identity → discovered → wishlist → stamps` 순서로 페이지를 만든다.
- 발견/예정 항목이 지정된 크기로 chunk된다.
- 빈 발견/예정/도장 상태도 책 안의 페이지로 생성된다.
- `getPassportSectionIndexes`가 책갈피 시작 인덱스를 정확히 계산한다.
- 도장된 저장 이벤트는 예정 장에서 제외된다.

수동 확인:

- 발견 카드가 많은 계정에서 책갈피 `발견/예정/도장` 이동이 자연스러운지 확인한다.
- 작은 화면에서 책갈피와 하단 탭바가 겹치지 않는지 확인한다.
- 여권 페이지 안의 텍스트가 잘리지 않는지 확인한다.

## 10. 비범위

이번 작업에서는 다음을 하지 않는다.

- 새로운 보상 정책 추가
- 위치 인증 추가
- 도장에 티켓 또는 토스포인트 보상 연결
- 홈 카드 추천 정책 변경
- 포인트 교환 정책 변경

이번 작업은 `/passport`의 경험을 “탭 3개”에서 “하나의 여권 책”으로 바꾸는 데 집중한다.
